## 1. System Map After First Pass

The studio is a hyper-modular Python package (`src/arbitr8der/`) with clean subsystem
boundaries. No file exceeds 1,000 lines.

- **Vessel state machine** (`vessel/vessel_state_machine.py`): 3 states — Full_Stop →
  Battery → Full_Forward. Always starts in Full_Stop, no persistence. Transitions are
  explicit. ARMED execution requires Full_Forward AND an armed wallet profile.
- **Config** (`config/config_settings.py`): typed pydantic-settings, `AR8_` env prefix.
  Long, self-explanatory variable names per Theories. Thresholds for PAPER vs ARMED
  (edge, hold, slippage, loss caps) are all here.
- **Market data hot state** (`market_data/hot_state.py`): thread-safe in-memory snapshot
  with a `generation` counter bumped on every update. AI reads one immutable `HotSnapshot`
  per decision cycle. No DB waits in update path. Matches Theories "machine RAM for hot
  data" directive.
- **Event envelope** (`market_data/event_envelope.py`): immutable, `MappingProxyType`
  payload, stamps `received_at_monotonic_ns` and `received_at_utc` for latency tracing.
- **Integrations** (`integrations/`): Kalshi REST + WS (JWT via RSA-PSS auth,
  `kalshi_auth.py`), Binance spot WS, Coinbase spot WS, Polymarket poll, Coingecko poll.
  Aux streams are context only — never execution triggers (per Theories).
- **Connection manager** (`integrations/connection_manager.py`): central lifecycle; routes
  events to HotState + EventRepository; recomputes best bid/ask from orderbook levels on
  delta; publishes `StreamHealthCounters`.
- **Execution** (`execution/`): `ExecutionEngine`, `RiskManager`, `Inventory`,
  `price_models`. Black-Scholes-style `fair_yes_probability` using annualized sigma
  (BTC 0.65, ETH 0.85). Kalshi fee curve `0.07 * P * (1-P) * 100` cents. Exits re-check
  post-latency book. Risk gates: session floor, rolling floor, daily/batch loss caps,
  lane cooldowns, same-batch reentry lock.
- **Strategies** (`strategies/strategy_profiles.py`): single `AI_Operator` profile with
  per-asset and per-lane (BTC:YES, BTC:NO, ETH:YES, ETH:NO) edge overrides and contract
  caps.
- **Wallets** (`wallets/`): PAPER auto-downgrades from ARMED if creds missing. PAPER
  balance pulled live from Kalshi if `paper_start_balance_cents == 0`.
- **Storage** (`storage/`): WAL SQLite (`sqlite_connection_manager.py`), schema migrations
  (v1 market_events/health/wallet/sensor, v2 trade_journal/archive_log), repos, and
  `ArchiveManager` that dumps a 72HR-style JSON archive and truncates hot tables.
- **CLI** (`cli/`): typer app with `status`, `vessel {stop|battery|forward}`,
  `battery start`, `forward start`, `archive list`. ARMED requires typing "ARMED".
- **Workflows**: `BatterySession` (soak, sensor loop, 3s health sampling) and
  `FullForwardSession` (trading loop, 1s tick, archive on shutdown).

## 3. Key Observations / Risks Noted (for later agents & myself)

1. **No stateful orderbook reconstruction.** `connection_manager._update_hot_state_from_orderbook`
   treats every delta as a fresh bid=ask=delta price. It does *not* maintain a running
   levels book. Snapshots compute best bid/ask from level arrays, but between snapshots the
   "book" is just the last delta price. This is acceptable for entry/exit *pricing* but means
   the hot book is not a true depth book — a known limitation flagged in the dev log.
2. **Exit profitability re-check is price-only.** `ExecutionEngine.exit_trade` recomputes PnL
   from post-latency bid, but the *entry* path uses `random.uniform(0.060, 0.100)` simulated
   latency and does not actually submit to Kalshi (PAPER is simulated). So "paper physics"
   fidelity depends entirely on this synthetic latency matching real fill latency — a caveat
   the Theories doc cares about ("paper physics must match ARMED").
3. **PAPER fair-value model is the only alpha signal.** Edge = `fair_cents - ask - fees -
   slippage`. There is no momentum/technical confirmation despite the profile field
   `min_confirmed_move_bps` and `strategy_type="momentum"` — those fields are defined but
   unused in `evaluate_trade`. The "momentum" label is currently aspirational.
4. **Redundancy watch (Theories: "inspect for where we bug ourselves").** Vessel safety is
   duplicated: `vessel_state_machine` already blocks Full_Forward→ARMED without wallet, AND
   `cli_main.forward_start` does its own ARMED confirmation, AND `RiskManager` gates entries.
   Good defense-in-depth, but worth a periodic audit so three killswitches don't drift apart.
5. **Aux stream wiring is partial.** `ConnectionManager._start_all` only launches Kalshi REST/WS
   and Binance WS. Coinbase, Polymarket, Coingecko clients exist but are **not** started or
   routed into HotState by the connection manager. Theories lists them as required context
   overlays; currently they are dead code in the live path. Flag for a future "wire aux
   streams" task.
