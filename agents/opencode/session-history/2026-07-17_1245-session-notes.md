# ARBITR8DER Agent Session Notes — 2026-07-17 12:45-1:00 PM PDT

## Session Summary
Ran 4 PAPER sessions (3 quick + 1 timed driver that hung). No realized PnL. Two paper
positions were opened but abandoned on session exit because paper inventory is in-memory.

## Problems Encountered

### 1. Market Depth Too Thin
BTC YES ask size was consistently 1-2 contracts. ETH YES ask size was 0 at times.
Large trades blocked by "insufficient depth" check in `enter_trade_ai()`.
**Fix**: Need a `--size` or minimum depth check before attempting trades.

### 2. Price Drift Between Snapshot and Execution
The engine simulates 60-100ms latency. During that latency window, prices moved
dramatically — BTC YES went from 50c to 18c in one case. This means the snapshot
the AI sees is stale by the time the trade executes.
**Fix**: Either reduce latency, or re-check and report drift to the AI.

### 3. Paper Inventory Is In-Memory
Positions created in one session are lost when the session exits. There's no
persistence layer for paper positions. The archive stores the session metadata
but does NOT restore inventory on next startup.
**Fix**: Persist paper positions to SQLite and restore on session start.

### 4. No Auto-Settlement at Market Close
When a 15-minute binary market settles, paper positions are not automatically
closed/settled. The PnL is never realized unless the AI explicitly calls `sell`
before session end. Since positions die with the session, all paper PnL is
unrealized and unrecoverable.
**Fix**: Add settlement watcher thread that polls Kalshi for market resolution
and settles paper positions automatically.

### 5. No Strike Price Resolution
The `active_universe` always shows `strike: 0`. Without the strike price, we
cannot tell if the binary is ITM or OTM. The Black-Scholes edge model returns
`edge=-999.0c reason=no strike or spot` for every opportunity.
**Fix**: Fetch the full market detail from Kalshi REST (GET /markets/{ticker})
to get the strike price during universe discovery.

### 6. Binance WebSocket Not Delivering Data
The `binance:spot_ticker` stream has 0 messages in every session. Spot data only
appears via the REST-based 30-tick refresh in the monitor thread. This means the
hot state's spot feeds are never updated live.
**Fix**: Investigate Binance WS subscription — likely wrong stream name or
channel format for the 15-min binary tickers.

### 7. REPL + Piped stdin = Fragile
Feeding commands via stdin works for one-shot sequences but breaks for timed
workflows. The `input()` call blocks until stdin provides a line or hits EOF.
Once stdin is consumed, EOFError ends the session.
**Fix**: Add a `--script FILE` mode or a non-interactive command queue with
timing support.

## Features Needed

### A. Historical Price Database
Strategy: Use past 72h of BTC/ETH 1-min candles to calculate up/down probability
in 15-min windows. Compare historical probability vs Kalshi market-implied
probability → edge signal.

Requirements:
- Binance REST: GET /api/v3/klines (1m candles, 72h = 4320 candles)
- Store in SQLite `price_history` table
- On session start, backfill missing data
- Calculate: P(up) = count(close > open 15m later) / total windows
- Compare to Kalshi YES price → edge = historical_P - market_P

### B. Persistent Paper Positions
- Save PaperPosition to SQLite on create
- Restore on session start
- Settle at market close automatically

### C. Market Detail Resolution
- During universe discovery, fetch market detail from Kalshi to get strike price
- Store strike in active_universe
- Enable Black-Scholes edge model
