# Gemini Trading Journal - 2026-07-17 (Deep-Dive & Evolution Refresh)

## 1. Context of Project Evolution ("The Molt")
By analyzing the legacy systems (`old_ARBITR8DER`, `old_agents`, `agents/chats/`), I have traced the structural and strategic lessons that this current system is designed to molt from:

- **Strategic Bloat → Laser Focus**:
  - *Old*: Tried to trade all 21 series (7 assets × 3 types) × YES/NO lanes. This led to "strategy selectivity starvation" and massive bleeding in toxic lanes (e.g., SOL:NO, DOGE:NO, BNB:NO) that ran contrary to the underlying realized transaction truth in the Kalshi CSVs.
  - *New*: Strict focus **only** on BTC and ETH 15-minute markets (`KXBTC15M*`, `KXETH15M*`). Coingecko, Polymarket, and spot feeds serve strictly as slow/macro context overlays, never as direct execution triggers.
- **Architectural Complexity → Hyper-Modularity**:
  - *Old*: Codebases had 2,200+ line reactor files (`engine_reactor.py`), custom POSIX shared memory components that broke native Windows execution, and fragile process orchestration loops.
  - *New*: Built on a hyper-modular scaffolding (no files > 1,000 lines). Subsystem responsibilities are partitioned cleanly:
    - [sqlite_connection_manager.py](file:///C:/Users/itsji/ARBITR8DER/src/arbitr8der/storage/sqlite_connection_manager.py) (WAL-mode, thread-safe, auto-migrating).
    - [hot_state.py](file:///C:/Users/itsji/ARBITR8DER/src/arbitr8der/market_data/hot_state.py) (Hot state stored in memory with version-tracked snapshots for zero-latency AI reads).
    - [connection_manager.py](file:///C:/Users/itsji/ARBITR8DER/src/arbitr8der/integrations/connection_manager.py) (Central websocket/REST manager).
- **Execution & Parity Pitfalls**:
  - *Old*: Suffered from the "15m YES contract settlement trap" (where YES positions held into expiry settled at 0c, wiping out profits) and "post-latency exit slippage" where latency during REST execution turned profit-window targets negative.
  - *New*: Exits re-verify net profitability after post-latency book refresh. Headless design (visual UI completely deleted) protects speed and AI machine-readability.

## 2. Technical Blueprint: Core Mechanics
- **Probability Pricing Model**:
  - Volatility mapping is annual: $\sigma_{BTC} = 0.65$, $\sigma_{ETH} = 0.85$, defaulting to $0.80$.
  - Probability CDF calculations scale dynamically based on exact seconds remaining to strike close.
  - Enforces Kalshi's fee curve model: $Fee = 0.07 \times P \times (1 - P) \times 100$ cents.
- **Vessel States**:
  - `Full_Stop`: All streams/connections closed, zero execution.
  - `Battery`: Exchange connections active, database logger logging, live hot state soaking, zero trading.
  - `Full_Forward`: Complete engine activation. Real-money `ARMED` profile requires explicit console confirmation (safety latch).
